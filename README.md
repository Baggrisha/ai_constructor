# AI Constructor

Начальная реализация редактора для macOS 14+ / Apple Silicon. Модель документа,
транзакции и файловое хранение находятся в платформенно-независимом Rust-ядре;
нативный интерфейс SwiftUI обращается к нему через созданные UniFFI-привязки.

**Статус:** Rust-ядро M0 стабилизировано. Финальный GUI-прогон выполнен на
macOS 27.2 arm64; XCTest и macOS 14–15 не проверены, поэтому M0 не объявлен
полностью принятым.

## Реализовано в исходном коде

- Создание и открытие проекта-папки, поиск, переименование и недавние проекты;
  при открытии записи недавнего проекта сверяется `projectId`; если манифест
  повреждён, папку нужно выбрать явно. Архивация переносит запись в раздел
  «Архив» на этом Mac, не перемещая файлы проекта. Дубликат получает новые ID
  проекта, чатов и сообщений; история и контрольные точки переносятся с
  адаптацией идентификаторов, а отслеживаемые generated-файлы и записи защиты
  `blockedGenerated` сохраняются. Дублирование не поддерживает проекты с
  записями агента. Переносимый снимок — другая операция: он сохраняет ID проекта,
  отслеживаемые чаты и сообщения вместе с их вложениями, остальные ресурсы,
  историю, контрольные точки и архивы конфликтов, включая защиту generated-файлов;
  исключает машинно-локальное состояние, grants доступа и `.git`. Снимок можно
  создать из сохранённого проекта без нерешённых конфликтов: отслеживаемые
  generated-файлы с переносимой защитой не являются препятствием. Снимок может
  содержать приватные данные; проверьте его перед передачей или публикацией.
  Удаление проекта в Корзину требует подтверждения и закрытия его сессий.
  В новых проектах `.gitignore` исключает локальный кэш, `.env` и обычные
  корневые каталоги сборки; документ, `src/`, история и чаты остаются
  доступными для Git. Существующий `.gitignore` не переписывается при открытии.
- Новый проект содержит страницу с корневым фреймом 1440×900. Изменения его
  названия и размеров объединяются до потери фокуса или паузы 500 мс и затем
  сохраняются транзакцией без обращения к ИИ. В транзакцию попадают только
  реально изменённые свойства; метаданные остальных не перезаписываются.
  Некорректный или не сохранённый ввод остаётся в форме и блокирует закрытие
  или переключение проекта; его можно исправить или повторить сохранение. Если
  разрешение конфликта временно откладывает черновик фрейма, после разрешения
  конфликтов черновик не применяется автоматически: его нужно явно применить.
  Доступны отмена и повтор. При ошибке чтения или записи настройки панелей
  текущий выбор действует только до закрытия приложения. Интерфейс показывает
  только контур первого фрейма, а не содержимое документа.
- Rust-ядро поддерживает дерево узлов, типизированные транзакции с проверкой
  ревизии, отпечатка, области действия и целостности ссылок. Определения
  токенов, переменных, действий, анимаций и модулей сохраняются и проверяются;
  интерфейс и механизм исполнения для них пока не реализованы.
- Локальные чаты с текстовыми сообщениями, вложениями из ресурсов, поиском,
  переименованием, архивированием и ответвлениями. Это файловая история,
  а не подключение к модели ИИ. Изменения переписки сохраняются в JSON/JSONL.
- Импорт и перепривязка PNG, JPEG, GIF, WebP, SVG, TTF, OTF и TTC в ресурсы с адресацией по
  хешу: не более 50 МиБ на файл, 64 Ми пикселей на изображение, 64 шрифтовых
  лиц в TTC и 128 таблиц на лицо. Превышение лимитов возвращает
  `IMPORT_LIMIT_EXCEEDED`; некорректные файлы отклоняются отдельно.
  Для шрифтов до обхода проверяются версия, массив смещений коллекции и
  диапазоны всех таблиц каждого лица; структурные ошибки дают `INVALID_DOCUMENT`.
  Эти же проверки действуют при загрузке шрифта для layout, не только при импорте.
  FIFO и другие нерегулярные файлы отклоняются; на Unix открытие неблокирующее,
  чтобы проверка типа не зависела от появления writer. SVG с активным содержимым
  или внешними ссылками отклоняется.
  Повреждённый ресурс можно перепривязать при отсутствии других несогласованных изменений;
  обнаруженная повреждённая версия сохраняется в `conflicts/`.
- Диагностика внешних изменений и выбор сохранённых версий там, где ядро
  может проверить доступные варианты. При незавершённом журнале и внешней
  версии выбор целого проверенного старого или нового снимка доступен также
  тогда, когда маркер манифеста совпадает с одной из известных версий.
  Выбор проверяется по состоянию диска и локальному поколению; обе проверенные
  версии и обнаруженные внешние данные сохраняются до записи. Неизвестный
  вытеснённый inode сохраняется в `retained/`, а публикация прерывается.
  Неполные или неподдерживаемые снимки не предлагаются. При неоднозначных
  или повреждённых данных запись либо открытие блокируется, а не угадывается.
  Если в полях фрейма остался черновик, выбор конфликта и восстановления
  заблокирован до завершения ввода или явного подтверждения удаления черновика
  в диагностике. Уже применённые изменения при этом не отменяются.
- Длительные операции в интерфейсе запускаются вне основного потока и
  поддерживают запрос отмены. После начала публикации отмена может оказаться
  слишком поздней. Наблюдатель macOS использует FSEvents, а при неудаче его
  запуска — периодическую диагностику; это не замена резервным копиям.
- `project.json` и `document.json`, история транзакций, ревизии и контрольные
  точки с контентно-адресуемыми копиями файлов.
  Восстановление возвращает документ и учтённые исходники/ресурсы из точки.
  Позднее добавленные учтённые исходники удаляются из рабочего дерева, но их
  содержимое сохраняется в контентно-адресуемых копиях и журнале транзакции.
  Позднее добавленные `assets/` не удаляются, поскольку история чатов не
  откатывается; ресурсы, к которым привязаны сообщения, сохраняются в документе
  и доступны как вложения.
  Восстановление, меняющее содержимое, набор файлов или режимы, записывается
  журналом; Undo/Redo возвращают файлы и режимы и работают после повторного
  открытия проекта. Новые точки хранят три POSIX-бита исполняемости зависимостей;
  при восстановлении эти биты применяются, а журнал позволяет отменить и повторить
  переход, включая изменения только режима файла.
  Старые точки без этих метаданных сохраняют текущие режимы существующих файлов.
  Если требуется создать отсутствующий файл, обычное восстановление останавливается
  для явного подтверждения; подтверждённое восстановление создаёт его без
  execute-битов. Подтверждение привязано к поколению сессии и устаревает после
  изменения проекта.
  Внешние изменения и неоднозначные пути, в том числе алиасы регистра и
  нормализации имён, блокируют небезопасное восстановление. В Linux восстановление
  с изменением файлов также отклоняется для каталогов с casefold и если
  соответствующий флаг файловой системы нельзя проверить. Остальные права, ACL и
  расширенные атрибуты не гарантированно восстанавливаются.
- Блокировка записи, журнал с копиями прежних и новых данных, публикация
  манифеста последней и восстановление при следующем открытии. Заменяемые
  файлы атомарно обмениваются с сохранением вытеснённых inode; создание и
  удаление используют атомарное перемещение без перезаписи. При обнаружении
  неоднозначного состояния проект открывается только для чтения; некоторые
  повреждения блокируют открытие. При отсутствии нужных файловых примитивов
  запись завершается ошибкой, без перехода на обычный перезаписывающий rename.
  Проверены отдельные сценарии, а не все возможные отказы и файловые системы.
- Считываемый документ с более новой версией схемы открывается только для
  чтения; манифест должен сохранять обязательные поля текущей версии. Неизвестные
  поля манифеста также блокируют запись и сохраняются в исходном виде.

Неизвестное содержимое распознанных узлов сохраняется для открытия только на
чтение; некорректный JSON или несовместимые поля могут блокировать открытие без
перезаписи файлов. Автоматических ответов ИИ, импорта макетов, генерации и
веб-предпросмотра пока нет.
Векторная модель поддерживает примитивы `rect`, `circle`, `ellipse`, `line`,
`polyline`, `polygon` и команды путей `moveTo`, `lineTo`, `curveTo`, `close`;
геометрия проходит структурную и числовую проверку. Размер векторного узла с
`hug` — габариты объединения примитивов и путей; для `curveTo` учитываются
экстремумы кривой, а не управляющие точки. Расчёт границ сохраняет остаточную
точность для больших координат; если её недостаточно, операция завершается
`INVALID_DOCUMENT`, не выдавая приблизительный размер. Пустая геометрия и команды
рисования без начального `moveTo` отклоняются (`UNSUPPORTED_FEATURE`); переполнение
также возвращает `INVALID_DOCUMENT`. Модель не описывает трансформации отдельных
фигур/путей и обводку (`stroke`), поэтому они не входят в расчёт габаритов.
Неизвестные поля/формы сохраняются для открытия только на чтение; редактирующие
транзакции с ними отклоняются.

## Контракт документа и транзакций

`schemas/project-document.schema.json` описывает формат документа версии 1.
JSON — формат обмена через `ProjectSession::apply_transaction` в Rust и
`applyTransaction(transactionJson:)` в Swift/UniFFI; операции разбираются в
типы ядра. Проверки ссылок, ограничений и области действия выполняются ядром,
в дополнение к ограничениям JSON Schema. Каждая успешная транзакция увеличивает
ревизию на единицу; ошибка любой операции отклоняет всю транзакцию.

Транзакция содержит `transactionId` (новый UUID), `baseRevision`,
`baseFingerprint`, `origin` (`user`, `import`, `agent`), непустой
`scopeNodeIds` и непустой список `operations`. Ревизию и отпечаток нужно брать
из одного актуального снимка `snapshot_json()` / `snapshotJson()`; устаревшая
пара отклоняется с `REVISION_CONFLICT`. Например, в Rust внутри функции,
возвращающей `Result`, для уже открытой сессии:

```rust
let snapshot: serde_json::Value = serde_json::from_str(&session.snapshot_json()?)?;
let root = snapshot["document"]["pages"][0]["rootId"].as_str().unwrap();
let transaction = serde_json::json!({
    "transactionId": uuid::Uuid::new_v4(),
    "baseRevision": snapshot["document"]["revision"],
    "baseFingerprint": snapshot["fingerprint"],
    "origin": "user",
    "scopeNodeIds": [root],
    "operations": [
        {"type": "setProperty", "nodeId": root, "path": "/name", "value": "Главный фрейм"}
    ]
});
let updated_snapshot = session.apply_transaction(&transaction.to_string())?;
```

Поддерживаемые операции и их поля:

| `type` | Поля и поведение |
| --- | --- |
| `insertNode` | `parentId`, `index`, `node`: новый узел должен содержать `parentId` этого родителя, пустые `children` и `propertyMeta`; его UUID и UUID родителя входят в область. |
| `removeNode` | `nodeId`: удаляет поддерево; область включает родителя и все удаляемые узлы. Корень страницы удалить нельзя. Оставшиеся недопустимые ссылки приводят к отказу. |
| `moveNode` | `nodeId`, `parentId`, `index`: область включает узел, старого и нового родителя. Индекс считается после извлечения узла из старого родителя; перенос в собственное поддерево запрещён. |
| `setProperty` | `nodeId`, `path`, `value`: изменяет поддерживаемое свойство узла. `null` снимает необязательное свойство; для связанного свойства сначала нужно удалить привязку. |
| `setBinding` | `nodeId`, `path`, `binding`: значение привязки — объект `{"type":"token","tokenId":"00000000-0000-4000-8000-000000000001"}` или `{"type":"variable","variableId":"00000000-0000-4000-8000-000000000001"}` с UUID существующего источника; явный `null` удаляет её. Тип источника должен совпадать с типом свойства. |
| `setToken` | `token` с полями `id`, `name`, `value`; значение — строка, число или логическое значение. |
| `upsertAction` | `action` с `id` и `kind`; типы `kind.type`: `navigate`, `openUrl`, `toggleVisibility`, `playAnimation`, `setVariable`, `toggleVariable`. |
| `upsertAnimation` | `animation` с `id`, `nodeId`, `property`, `durationMs`, `delayMs`, `keyframes`. Необходимо минимум два кадра с возрастающими `offset` от 0 до 1 и значениями типа свойства. |
| `upsertCodeModule` | `codeModule` с `id`, `path`, `props`, `events`; `path` — существующий учтённый файл `.ts` или `.tsx` внутри `src/user/`. Типы `props`: `boolean`, `number`, `string`; события — имена без произвольного кода. |
| `setViewport` | `nodeId`, `width`, `height`: задаёт положительные конечные размеры корневого фрейма. |

Поля `action.kind` зависят от типа: `navigate` требует `pageId`, `openUrl` —
`url` с HTTP(S)-схемой, `toggleVisibility` — `nodeId`, `playAnimation` —
`animationId`, `setVariable` — `variableId` и `value`, `toggleVariable` —
`variableId` логической переменной.

Можно вставлять `frame`, `group`, `text`, `image`, `vector`, `button`,
`input`, `textarea`, `checkbox`, `select`, `componentInstance` и
`codeComponent`. Экземпляр ссылается на существующее определение компонента;
операции создания определений компонентов и их визуальный редактор пока не
реализованы. `codeComponent` требует существующий `moduleId`; его `props` и
события проверяются по объявленному контракту модуля. Это данные модели,
а не работающий пользовательский React-компонент.

Для `setProperty` доступны `/name`, `/layout/x`, `/layout/y`, `/layout/w`,
`/layout/h`, `/layout/flow`, `/layout/widthMode`, `/layout/heightMode`,
`/sourceBounds`, `/sourceDensity`, `/responsive`, `/style/fill`,
`/style/color`, `/style/opacity`, `/style/fontFamily`, `/style/fontFallback`,
`/style/fontAssetId`, `/style/fontSize`, `/style/fontWeight`, `/style/fontStyle`,
`/style/lineHeight`, `/style/letterSpacing`, `/style/textWrap`,
`/a11y/label`, `/a11y/alt` и `/events/<имя>`. Свойства `/content/text`, `/content/placeholder`,
`/content/assetId`, `/content/vector`, `/content/componentId`, `/content/moduleId`, `/content/props`
разрешены только соответствующим типам узлов. Событие ссылается на UUID действия,
а не на текстовую подпись. Модель хранит контуры как типизированные команды,
поток `row`/`column`, отступы и размеры `fixed`/`hug`/`fill`.

Обновление общего токена, действия, анимации или модуля требует включить в
`scopeNodeIds` все затронутые узлы; для анимации и действия с целевым узлом
также нужен сам целевой узел. Агент не может изменить защищённое свойство,
удалить узел с защитой или обойти защиту через общий токен/модуль. Пользователь
может установить или снять защиту через `setProperty`: для `/layout/w` путь
равен `/propertyMeta/~1layout~1w/agentLocked`, а значение — `true` или `false`.
Блокировка и её снятие участвуют в истории отмены и повтора.

Отдельной транзакции создания переменной пока нет; ресурсы создаются и
перепривязываются через API проекта, не через `apply_transaction`. Ресурс
учитывается как `assets/<sha256>.<ext>`, а его хеш должен совпадать с именем.
Модуль ссылается на файл, а не содержит исходный код внутри документа.
Метаданные действий и анимаций не выполняются: это не предпросмотр.
Ядро также преобразует координаты через иерархию, масштаб и позицию холста,
плотность исходника и явно выбранный breakpoint. `hug` реализован для текстов,
изображений, векторной геометрии, экземпляров компонентов по шаблону и
контейнеров с flow-layout; остальные узлы без известных intrinsic-метрик
отклоняются. Для текста `hug` использует Unicode-shaping и переносы `cosmic-text`.
Ширина `hug` текста — максимальная ширина явной строки без автоматического переноса,
высота `hug` учитывает фактически выделенную ширину (`fixed`, `fill` или
растяжение по поперечной оси).
Явные разделители строк (классы Unicode BK/CR/LF/NL) образуют отдельные
layout-абзацы; CRLF считается одним разделителем, пустая завершающая строка
сохраняется. Для пустого текста ширина равна 0, высота — одной строке.
Unicode BiDi, combining marks, лигатуры и emoji-кластеры формирует shaping,
а не подсчёт кодовых точек. Масштаб холста и source density применяются после
измерения и не меняют метрики в CSS-пикселях. Для `/layout/x`, `/layout/y`,
`/layout/w` и `/layout/h` поддерживаются привязки к числовым token/variable;
явный override выбранного breakpoint имеет приоритет над привязкой. Некорректный
effective-размер даёт `INVALID_DOCUMENT`; привязка размера на оси с режимом `hug`
или `fill`, а также циклическая зависимость размеров дают `UNSUPPORTED_FEATURE`.

Типографика задаётся в `style`: `fontSize` и `lineHeight` — логические пиксели,
`letterSpacing` — логические пиксели между символами, `fontWeight` — 1–1000,
`fontStyle` — `normal`/`italic`/`oblique`, `textWrap` — `none`/`word`/
`wordOrGlyph`. По умолчанию используются 16 px, вес 400, normal и
`wordOrGlyph`; высота строки рассчитывается по метрикам выбранного шрифта.
`fontFamily` задаёт установленное семейство, `fontFallback` — одно явно
разрешённое установленное резервное семейство. `fontAssetId` выбирает
импортированный проектный шрифт; для коллекции с несколькими семействами
нужно дополнительно указать `fontFamily`. Абсолютные пути не открываются как
имена шрифтов. Нет указанного семейства/начертания — `MISSING_FONT`, нет глифа
в выбранных семействах — `MISSING_GLYPH`; неявной подмены нет. Файлы ресурсов
проверяются по хешу, а изменённый файл вызывает `REVISION_CONFLICT`.
Синтетические bold/italic не создаются: требуется установленное начертание
или подходящий диапазон variable `wght`; иначе возвращается `MISSING_FONT`.
Неизвестные и связанные с токенами типографические значения без разрешённых
значений не измеряются (`UNSUPPORTED_FEATURE`), вместо молчаливого расчёта по
дефолтам. `fontAssetId` не принимает ресурс изображения и участвует в обычных
транзакциях, истории и проверке зависимостей проекта.

При отсутствии явного семейства выбирается первое доступное из Arial,
Helvetica, DejaVu Sans, Liberation Sans, Noto Sans. Наличие и версии системных
шрифтов зависят от устройства; список считывается один раз за процесс, после
установки шрифта приложение нужно перезапустить. Для воспроизводимости между
устройствами используйте один и тот же проектный файл шрифта, не системный
fallback, и одну версию ядра. Текущая оболочка ещё не использует этот механизм
для текстового рендеринга, поэтому совпадение с будущим холстом не заявляется.

## Что ещё не сделано для M0

Реального поддерживаемого перехода между версиями схемы пока нет: начальный
`b9a27b4` и последующий `0665db3` оба использовали версию 1. Реестр миграций
пуст; неизвестная старая версия отклоняется без выдуманной конвертации.
Каркас предназначен для явно зарегистрированных переходов с проверкой исходной
и целевой схемы: под проектной блокировкой он проверяет снимок, сохраняет
манифест и прежние версии всех изменяемых файлов в
`Application Support/AIConstructor/Backups/<projectId>/<backupId>/` и применяет
изменения через общий журнал. Файлы, создаваемые впервые, отмечаются как
отсутствовавшие. Несовершённая копия помечена `.preparing-*`; её наличие не
означает успешную миграцию. Пока этот путь проверяется только синтетическими
тестами, а не настоящей миграцией.

Полная модель компонентов и свойств A.6–A.9, автоматическое семантическое
слияние внешних изменений и исчерпывающая обработка отказов также не завершены.
Поддерживаемые варианты ручного разрешения не заменяют независимую приёмку
всех сценариев T10–T11.
Отслеживаемые файлы `src/generated/` и записи защиты `blockedGenerated`
переносятся вместе со снимками и дубликатами. Они не синхронизируются с документом:
автоматической генерации и разбора AST нет.
Папка проекта может содержать приватную переписку и визуальные образцы;
проверьте их перед публикацией. Git-команды приложение не запускает.

Каждая опубликованная транзакция оставляет журнал, его копии и вытеснённые
файлы в `.aic-local/retained/<transaction-id>/`. По умолчанию хранение
**не ограничено**: автоматического удаления нет. В macOS в меню
«AI Constructor → Настройки…» можно выбрать конечное число от 0 до 4294967295;
перед применением обязательно подтверждение предупреждения. Отмена не меняет
настройку. Она находится в `~/Library/Application Support/AIConstructor/retention-settings.json`,
вне Git и папки проекта. При ошибке чтения действует неограниченное хранение,
неизвестный файл настроек не перезаписывается. Изменение настройки, запуск и
открытие проекта сами по себе очистку не запускают: лимит применяется после
следующего фактически завершённого сохранения соответствующего проекта.

Единица учёта — **одна завершённая транзакция сохранения проекта**, а не
количество файлов или контрольных точек: в неё могут входить изменения
документа, чатов, ресурсов и другие записи, опубликованные одним сохранением.
Отдельно для каждого проекта среди распознанных завершённых транзакций
защищаются N самых новых по `storageGeneration` (при равенстве — по UUID);
остальные рассматриваются от старых к новым. Незавершённые и активные журналы,
записи без проверяемого признака завершения, незнакомые каталоги, символьные
ссылки и чужие файлы не удаляются. Старые записи, созданные до появления
признака завершения, не считаются доказанно завершёнными и сохраняются даже
при конечном лимите. Распознанная запись с изменённым файлом или неизвестным
содержимым учитывается, но не очищается. При наличии любого архива в
`conflicts/` очистка всего проекта консервативно откладывается. Поэтому реальное
количество записей может превышать выбранное N.

Перед удалением сверяются состав и хеши записи. Под блокировкой проекта запись
атомарно переименовывается в `.pruning-<transaction-id>` и удаляются только
перечисленные проверенные файлы. Маркер остаётся до конца удаления; после сбоя
незавершённое удаление возобновляется при следующем сохранении с конечным
лимитом. Неизвестные или изменившиеся файлы в таком каталоге остаются на месте.
Ошибка очистки не отменяет уже завершённое сохранение и сообщается в stderr;
повтор выполняется при следующем сохранении.

**Конечный лимит не гарантирует безопасность данных.** Сторонняя программа
может всё ещё держать старый файловый дескриптор и записать в вытеснённый inode
после проверки или удаления. Такая поздняя запись может быть безвозвратно
потеряна. Нет переносимой атомарной проверки, что все внешние дескрипторы
закрыты; время хранения, отсутствие видимых конфликтов или вызов `lsof` этого
не доказывают. Диагностика обнаруживает некоторые поздние записи, но не все
будущие. Вытеснённый inode не является неизменяемой резервной копией. Храните
независимые резервные копии и учитывайте приватность сохранённых файлов.
Гарантии не покрывают стороннюю порчу `.aic-local`, враждебные изменения
структуры каталогов или файловые системы без обещанной атомарности и
долговечности.

## Зависимости

- macOS 14 или новее, arm64.
- Rust stable 1.97+ и Cargo; зависимости закреплены в `Cargo.lock`.
- Для стеклянных системных материалов при компиляции нужен macOS 26+ SDK.
- Для Xcode-сборки и XCTest нужен полный Xcode с выбранным `xcode-select`.
  Для альтернативной сборки из терминала нужны Apple Command Line Tools,
  содержащие Swift и macOS SDK с SwiftUI/AppKit. Генерация привязок и сборка
  требуют доступ к crates.io при первом запуске; само приложение ничего не
  скачивает. Node пока не нужен: веб-ресурсы и экспорт не реализованы.

Лицензия исходного кода ещё не выбрана; сам по себе публичный доступ к
репозиторию не предоставляет лицензию на использование кода.

## Сборка и запуск

Из корня репозитория:

```sh
# Полный Xcode: Rust, генерация настоящего Swift UniFFI и приложение.
./scripts/build-macos.sh
open build/AIConstructor.app
```

Скрипт не перезаписывает уже существующий `build/AIConstructor.app`; перед
повторной сборкой перенесите старый результат в другое место. Для сборки без
полного Xcode, если выбранные Command Line Tools содержат подходящий SDK:

```sh
./scripts/build-macos-clt.sh
open build/AIConstructor.app
```

Второй сценарий вызывает `swiftc` с `-target arm64-apple-macosx14.0`, SDK
из `xcrun`, сгенерированными Swift-привязками и статической библиотекой Rust.
В Swift 6.4 SDK `@State` может требовать отсутствующий в CLT плагин
`SwiftUIMacros`; интерфейс использует существующий property wrapper
`SwiftUI.State` через локальный тип `StoredState` и не подменяет приложение.
Оба скрипта собирают debug-вариант и не подписывают приложение для
распространения. Xcode-проект: `apps/macos/AIConstructor.xcodeproj`; его схема
генерирует привязки перед компиляцией.
